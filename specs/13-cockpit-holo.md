# SPEC 13 — 操縦席の刷新（HOLO CANOPY ＋ 中央操縦桿）

状態: **Verified（2026-09-26 K1〜K3 全て Verified・run-all 24スイート365テスト ALL GREEN）** ／ 詳細設計: [13a K1](13a-k1-cockpit-hardware.md)・[13b K2](13b-k2-holograms.md)・[13c K3](13c-k3-lock-boot-sp.md) ／ [実装計画](13-implementation-plan.md) ／ 依頼: 「推奨方針でデザイン設計を作成」 ／ 前提: [SPEC-12](12-cockpit-concepts.md) 案A改（中央操縦桿）・SPEC-09〜11 Verified ／ 外部素材: 不要
確認用: [labs/cockpit-concepts.html](../labs/cockpit-concepts.html)「案A改 中央操縦桿」 ／ 画像: `labs/cockpit-shots/A2-center-*.jpg`

## 1. 目的と範囲

- **目的**: 操縦席の質感を機体・岩（SPEC-09/10）と同じ水準に上げ、情報を「視線の近く・1か所」に集約する。
  物理の操縦桿とスピードメーターで「操縦している」実感を出す
- **対象**: ASTEROID RUN の**操縦席視点のみ**（追跡視点・サイトの章は変更しない）
- **変えないもの**: ゲームのルール・操作・スコア計算・難度（CON-03）、レティクルの色・不透明度・合成順（CON-05）、
  オフライン動作（CON-01/02）、SP の既存機能（CON-04）

## 2. 決定事項（SPEC-12 での確認結果）

| 項目 | 決定 |
|---|---|
| 操縦桿 | **画面下中央に1本**（マウス／ドラッグの操作と1対1で傾く） |
| 画面左上の DOM HUD | 操縦席視点では**数値の行を廃止**し、操縦席内の表示に一本化（PC・SP とも）。ボタン（VIEW / LOCK / SOUND）は残す |
| パイロットの手 | 今回は入れない（別 SPEC） |
| ロックオン表示 | 入れる（レティクルは変えず、**別のホログラムの小札**で示す） |
| 起動演出 | 入れる（ゲームの進行は止めない。1.2 秒） |

参考の要点（詳細と出典は SPEC-12 §5.1）: 情報は操縦席の空間の中に配置する（閃光のハサウェイ／全天周囲モニター）、
警告は中央に昇格し色数を絞る（オブリビオン）、速度は常に見える物理計器に（オブリビオンの反省）、表示は簡素に保つ（Ξガンダム）。

### 3.2 起動演出（K-12）

`start()` 時に操縦席視点なら 1.2 秒の起動演出。**ゲームの時間・操作・当たり判定は止めない**（開始直後は低速で岩も遠い）。

| 時刻 | 起きること |
|---|---|
| 0.00 s | 計器台の発光線が中央から左右へ点灯 |
| 0.15 s | スピードメーターが点灯し、指針が 0→最大→現在値へ振れる（0.15〜0.90 s） |
| 0.30 / 0.45 / 0.60 / 0.75 s | シールド → 武装 → 上帯 → レーダーの順に、走査線で上から描き出される（各 0.2 s） |
| 0.90〜1.50 s | 中央に `SYSTEMS ONLINE` が出て消える |

- `prefers-reduced-motion` 時は演出なしで全表示（CON-06）
- 途中で視点を切り替えた場合・プレイ中に操縦席視点へ戻った場合は演出しない（即時表示）
- 起動音は追加しない（既存の `engineStart` のみ）

## 5. 技術設計

- `buildCockpit()` を差し替え。部品の生成は `Assets` に置かず AsteroidRun 内の新関数群
  `cockpitDash()` / `cockpitStick()` / `cockpitMeter()` / `holoPanel(w, h, cw, ch, draw)` に分ける（サイトでは使わないため）
- **ホログラムの共通部品** `holoPanel`: キャンバス・テクスチャ・板・`draw(ctx, w, h)`・`dirty` 判定用のキー関数を持つ。
  `redraw()` はキーが変わった時だけ描き直す（K-R15）。`{fontPx: [...], worldH, canvasH}` を持ち、文字の実寸テスト（K-R11）に使う
- 操縦桿のグリップは材質ごとに結合（ゴム・樹脂・金属・発光・赤）して 5 メッシュ以内に
- `cptFx` を拡張: `{greebles, bezels(=筐体数: メーター・レーダー投影器・操縦桿の台座), lamps, alertLamp, alertLight, stick, meter, holos, lockTag, boot}`
- ループ内（操縦席視点）: 操縦桿の傾き → ロック札の位置（レティクルと同じ投影を z -2.3 に） → `holos.redraw()` → 状態色の反映。
  旧 `drawDash()` の呼び出しを置き換える。被弾グリッチ（FX-06）は全ホログラムのキャンバスに適用
- 起動演出: `st.bootT`（実時間で進む）で各パネルの `material.opacity` と描き出し範囲を制御。`REDUCED` なら `bootT = 1.2` から開始
- DOM HUD: `hud()` は変更しない（テキストは生成され続ける）。CSS で数値行のみ隠す
- 輝度: ホログラム・発光線は HDR 倍率を上限 1.6 に抑え（ACES 後 .88 程度）、白飛び判定（Y > .98）に掛からないようにする。既存の輝度基準は動かさない

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| ホログラムが岩と重なって回避の邪魔になる | 中央域には置かない（K-R02 の域外）。加算合成で輝度を抑え、岩の輪郭を隠さない |
| SP で文字が小さい | `HOLO_SCALE` とフォント寸法を K-T12 で数値検証 |
| キャンバスの更新負荷 | 変化時のみ再描画（K-R15）。SP は解像度 .6 倍 |
| 明るさが変わり既存の輝度テストが崩れる | 岩の指標はホログラムを隠して測り、±10% を確認してから基準を更新 |
| レティクル（CON-05）への影響 | ホログラムはメインシーン・別マテリアル。K-T14 を K1 から常時実行 |
