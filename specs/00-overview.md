# SPEC 00 — 全体設計・SDD運用ガイド

VOID GATE の改修を SDD（仕様駆動開発）＋ TDD で進めるための共通仕様・運用ルールと、全 SPEC の一覧。
最初の方針書は [QUALITY_PLAN.md](../QUALITY_PLAN.md)（SPEC 01〜06・完了）、以降は SPEC ごとの方針書・詳細設計を参照。

## 0. SDD運用ルール

1. **仕様が先、実装は後**。各SPECは下表の状態を持つ（通常は `Draft → Approved → Implemented → Verified`）
2. 実装は **Approved になったSPECのみ** 着手する。仕様変更はSPEC改訂→再承認から
3. 各要件は一意ID（例: `AUD-01`）を持ち、受け入れ基準（AC）と1:1以上で対応する
4. Verified の条件: 受け入れ基準をブラウザ実測（デスクトップ+SP相当ビューポート）で全通過
   ＋コンソールエラー0＋性能予算内
5. 1SPEC=1コミット系列とし、コミットメッセージにSPEC番号を含める（例: `[SPEC-01] 機関砲SFX実装`）

| 状態 | 意味 |
|---|---|
| Draft / Approved | 設計中 / 承認済み（実装に着手してよい） |
| Implemented | 実装済み・検証待ち |
| Verified | 受け入れテストと目視で検証済み（現行） |
| Proposal / Decided | 方向性の検討中 / 案が決まり、詳細設計（別 SPEC）へ引き継いだ |
| Superseded | 後の SPEC で置き換えた（記録として残す。現行の仕様は置き換え先を参照） |
| Withdrawn | 実装後に撤去した、または採用しなかった（要点と撤去理由だけの短い記録） |

### 0.1 資料の管理ルール（[SPEC-16](16-docs-audit.md) で制定）

1. **README.md と DESIGN.md は「現在の姿」だけを書く**。撤去した機能の説明やスナップショットは残さない（経緯は specs と git 履歴）
2. **specs は決定の記録として本文を書き換えない**。後の SPEC で置き換えた場合は、冒頭に「置換: SPEC-xx」の注記を足し、状態を更新する。当時のテスト件数・日付はそのまま
3. SPEC を完了・置換・撤去したら、**同じコミットで下の一覧表・README・DESIGN.md を更新**する
4. 撤去した機能の試作物（labs の比較ページ・画像）は削除し、SPEC は要点・撤去理由・参照コミットに圧縮する
5. 資料と実装が食い違ったら、誤っている側を直す。実装が誤りならテストを追加して再発を防ぐ

## 1. 共通制約（全SPECに適用）

| ID | 制約 |
|---|---|
| CON-01 | 完全オフライン動作を維持する。外部CDN・外部URLへの実行時アクセス禁止 |
| CON-02 | 追加アセットは原則プロシージャル生成（Canvas/Web Audio/頂点加工）。ファイル同梱する場合もリポジトリ内 `libs/` `assets/` に置きオフラインを維持 |
| CON-03 | ゲームルール・操作・スコア計算は、それを目的とする SPEC（例: 09c セクター制・09e スコア体系）で明示した場合を除き変更しない |
| CON-04 | 既存のSP対応（横画面・FIREボタン・コンパクトHUD・回転ガイド・フルスクリーン選択）を退行させない |
| CON-05 | ポインター（レティクル）の色・透明度は変更しない（過去のユーザー指示） |
| CON-06 | `prefers-reduced-motion` 時は新規の激しい明滅演出を抑制する |

## 2. 性能予算（全SPECの上限）

| 項目 | デスクトップ | SP(ミドル) |
|---|---|---|
| 目標フレームレート | 60fps | 40fps以上 |
| 1フレームのJS処理 | < 8ms | < 16ms |
| draw call（ゲーム中の合計・SPEC-09d で改訂） | 155以下（影込み） | 140以下 |
| 追加メモリ(テクスチャ計) | < 32MB | < 16MB |
| 配布物サイズ増分 | 合計 +300KB以内（外部素材を採用しない場合はほぼ0） |

- 計測方法: `performance.now()` によるフレーム時間ログ＋Chrome DevTools。
  SPはビューポート812×375＋CPU 4x throttleで代替検証し、最終は実機確認

## 3. 実装アンカー（index.html 内の統合ポイント）

単一ファイル構成のため、各SPECは以下のシンボルを統合先として指定する（**関数名で検索して特定**する。行番号は書かない）。

| アンカー | 役割 |

| `SoundEngine` | 効果音・エンジン音の合成（SPEC-01/11） |

## 4. 外部素材の要否（サマリ）

**結論: 全SPECとも外部素材なしで実装可能**（プロシージャル生成が既定）。
ただし、さらに質を上げたい場合の任意アップグレード素材を以下に明記する。
採用する場合はダウンロードして同梱（CON-01/02）し、ライセンス表記をREADMEに追加する。

| 用途 | 既定(生成) | 任意アップグレード素材 | 入手先例 | ライセンス | 容量目安 |
|---|---|---|---|---|---|
| 小惑星テクスチャ | Canvasノイズ生成 | 岩石PBR(Color/Normal 512px) | ambientCG (Rock系) | CC0 | 300KB〜1MB |
| 爆発/射撃SE | Web Audio合成 | 実録SEサンプル(ogg) | freesound.org (CC0検索) | CC0のみ採用 | 50〜200KB |
| 環境反射(機体) | 手続き生成の宇宙（PMREM・SPEC-09b） | 宇宙HDRI(1K) | Poly Haven | CC0 | 500KB〜1.5MB |
| BGM | 合成ドローン(SPEC-01) | ループBGM(ogg) | 要制作 or CC0曲 | 要確認 | 1〜3MB |

- **CC0以外（CC-BY等）は帰属表記が必要になるため原則不採用**。採用時はREADMEにクレジット必須
- BGMは容量インパクトが大きいため既定では合成ドローンのみ。実曲が欲しい場合は別途相談

## 5. 検証環境

- デスクトップ: Chrome最新（プレビューブラウザ）
- SP相当: ビューポート812×375（横）/ 375×812（縦・回転ガイド確認）
- 実機: ユーザー所有のスマートフォン（GitHub Pages経由）
- リグレッション確認: `tests/run-all.js`（全スイート。実行中は消音）。目視はゲーム起動/終了、視点切替、ロックオン、
  被弾4回で大破、シールド CRITICAL 表示、FIREボタン、フルスクリーン選択、サイトの各章
