# SPEC 09c — Phase F3: パターンスポナー・公平性検証・セクター制

状態: **Verified (2026-09-23 phaseF3 21/21・run-all 15スイート241テスト ALL GREEN。密度の実測で V_LAT・空白・壁の構成を改訂 §3.6)** ／ 親: [SPEC-09](09-realism-gameplay-policy.md) G2 ／ 前提: F1 Verified（clearance / SHIP_SPHERES / RadialHull） ／ 外部素材: 不要

## 1. 目的

一様乱数の再配置（`respawn`）を、**読める局面**を作るパターン生成へ置き換える。
「避けられない配置」を機械的に排除し、難しさを「速度」だけでなく**局面の種類**で上げる。

### 現状
- `respawn(m, far)`: x∈±55, y∈±41 の一様乱数、z は -400〜-1000
- 速度: `speed += dt*6`、110→480 で 61.7 秒後に頭打ち
- 乱数は `Math.random`（再現不可）

## 3. 技術設計

### 3.1 生成の流れ

```js
// ゲーム側（loop 内）
spawnCursor -= sd;                       // 進んだ分だけ減らす
if(spawnCursor <= 0 && !breather){
  const pat = spawner.next({sector, speed: st.speed, t: st.time});
  place(pat, SPAWN_Z = -900);            // 空きプールから岩/コアを配置
  spawnCursor = pat.length + st.speed*.9;   // F3-05
}
// 通過した岩（z > 26）はプールへ戻す（現行の respawn(m,true) を releaseToPool(m) に置換）
```

- 開始時（`start()`）: 最初の 900 単位を SCATTER（セクター1密度）で満たす（現行の「開始直後から岩が見える」を維持）

### 3.2 パターン一覧

| 名前 | 形 | 主なパラメータ |
|---|---|---|
| SCATTER | 疎なばら撒き（現行に近い）。密度はセクター依存 | n, rRange |
| BIG_ONE | 中央付近に大岩 1（r 10〜14）+ 周囲に小岩 | — |
| WALL_GAP | 同じ奥行きに岩を敷き詰めた壁 + 穴 1 つ（穴の半径 ≥ 7） | gapR |
| SLALOM | WALL_GAP を 3〜4 枚、穴の位置を左右交互に | 壁間隔 = max(90, speed×shift/V_LAT) |
| TUNNEL | 移動する中心線を囲む岩の輪（密集帯の一本道） | 中心線のうねり幅 |
| DRIFT | 横方向に漂う岩群（vx ±6〜14） | n, vRange |
| COMET_STREAM | 小さく速い岩の帯が横切る（vx ±40〜60）、帯の高さ y を1つ選ぶ | band y, 予兆 1.5s |
| CORE_LINE | 通路上に並ぶコア 3〜5 個（回収が経路誘導になる） | — |

### 3.3 公平性検証（F3-04）

```
入力: pattern（岩の x, y, dz, r, vx, vy）, speed
1. dz で「断面」に分割（機体長 5.2 + 岩の最大半径の窓）
2. 各断面で 2D 占有グリッド（範囲 x∈±FX, y∈±FY, セル 2 単位）を作る
   セルが塞がる条件: 楕円 ((dx/(R+3.9))² + (dy/(R+1.6))² < 1)   … R は RadialHull の最大半径×スケール、
   3.9/1.6 は機体4球の外形（半幅 3.75 / 半高さ 約1.5）+ 余裕
   動く岩は断面を通過する時間内の移動量ぶん楕円を掃引
3. 断面 i の空きセルから断面 i+1 の空きセルへ移れるのは、
   距離 ≤ V_LAT × Δt（Δt = 断面間の dz / speed、V_LAT = 90 単位/秒、上下は 108）
4. 最初の断面の空きセルのどれかから最後の断面まで到達できれば合格（BFS）
```

- V_LAT は機体の追従（目標へ毎秒6、縦は8の指数追従。端から端への初速は 500u/s 超）の**半分未満の 90（縦 108）**を仮定（安全側）。当初値 45 は §3.6 のとおり過小だった
- 検証は生成時に1回（パターンあたり最大 5 回 × 断面数 × グリッド 46×34）。1回 1ms 未満を目標

### 3.4 セクター表（F3-07）

| # | 名前 | 速度上限 | パターンの重み | 岩サイズ | 新要素 |
|---|---|---|---|---|---|
| 1 | OUTER BELT | 220 | SCATTER 70 / BIG_ONE 15 / CORE_LINE 15 | 2〜8 | — |

### 3.6 実装時の改訂（密度の実測による）

当初値（V_LAT 45 / 空白 0.9 秒 / 壁は小岩 30〜36 個）で 600 秒のシミュレーションを行うと、視界（z −500〜0）の岩は
**平均 9〜15 個**（旧スポナーは約 21 個）、岩が 3 個未満の「ほぼ空」の時間が後半セクターで最大 **24%**、
SLALOM と TUNNEL はプール不足で大半が切り詰められていた（364 パターン中 644 個）。原因と対処:

| 原因 | 対処 |
|---|---|
| V_LAT 45 が実機の横移動の1/10程度と過小 → 壁の間隔が数百単位に伸びる | V_LAT 90 / 縦 108 |
| パターン間の空白 0.9 秒が高速時に長い無人区間になる | 0.35 秒 |
| 壁が小岩 30〜36 個でプール（46）を圧迫 | 大岩で同じ面積を塞ぐ: WALL_GAP 5×4=20 個、SLALOM 片側2列×4段×3枚=24 個、TUNNEL 5輪×5=25 個。SCATTER は 12 個/300 単位 |
| 切り詰めで壁の形が崩れる | 収まるまで最大 1.5 秒待機して置く |

改訂後: 視界の岩は全セクターで平均 **13〜16 個**、「ほぼ空」は **8% 以下**、切り詰めは 670 パターン中 82 個。
公平性（F3-T04）は 32,000 件すべて合格のまま。これ以上の密度はプール上限（draw call）が律速のため、
岩の InstancedMesh 化（F4 で岩の描画を刷新する際に検討）で引き上げる。

## 7. リスク

| リスク | 対策 |
|---|---|
| パターンが単調に感じる | 重みとパラメータ（穴の位置・うねり・密度）を乱数化。セクター5以降は全種を循環 |
| 公平でも「見えない」（霧で遠方が見えず反応できない） | FogExp2 の透過率は exp(−(密度×距離)²)。密度 .0026 では距離 400 で 34%、900 で 0.4% なので、実際に見えるのは約 400 から。最高速 640 では 0.6 秒しかない → F3-13 で霧を速度に応じて薄くし、**視認時間 ≥ 0.7 秒**をテストで保証 |
| 岩プール不足で密度が出ない | 切り詰めで破綻はしない。見た目の密度不足は F4 以降で InstancedMesh 化を検討（本フェーズでは行わない） |
