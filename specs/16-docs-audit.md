# SPEC 16 — 資料の棚卸し（2026-09-27）

状態: **Verified** ／ 依頼: 「仕様書系の資料が最新化されているか、古い資料の残骸や記載が無駄に残りすぎていないか確認。修正が必要なら方針を明確にしてから対応」
恒常的な管理ルールは [SPEC-00 §0.1「資料の管理ルール」](00-overview.md) に定めた。本書はその初回適用の記録。

## 1. 修正方針

| # | 方針 | 理由 |
|---|---|---|
| P1 | **README と DESIGN.md は「現在の姿」だけを書く**。撤去した機能の説明・スナップショットは残さない | 利用者・開発者が最初に読む資料。古い記述は現状と取り違える原因になる |
| P2 | **specs は決定の記録として本文を書き換えない**。後の SPEC で置き換えた内容は、冒頭に「置換: SPEC-xx」の注記を 1 行足し、状態を正しくする | 「なぜそうなったか」を追えるようにする。当時のテスト件数などは記録として残す |
| P3 | 状態の定義を SPEC-00 に明記し（Superseded / Withdrawn / Decided を追加）、一覧表と各書の状態を一致させる | 「Implemented のまま」「Draft のまま」の放置をなくす |
| P4 | **撤去（Withdrawn）した機能の試作物は削除**し、SPEC は要点と撤去理由・参照コミットだけの短い記録に圧縮する | 本番に存在しない物の資料・画像が最も「残骸」になりやすい。全文は git 履歴で参照できる |
| P5 | 一時的な報告書（HANDOFF.md）は、今も有効な知見だけ README に移して削除する | 完了報告は役目を終えている |
| P6 | 資料と実装が食い違う場合、**実装が誤りなら実装を直し、テストで再発を防ぐ** | 資料だけ直すと利用者向けの誤りが残る |
