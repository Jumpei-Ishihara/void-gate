## 0. 結論（要約）

| 軸 | 現状の根本原因 | 方針 | 効果が最も大きい施策 |
|---|---|---|---|
| 質感 | **トーンマッピングなし・環境反射なし・一様な環境光**。明るさを emissive と bloom に頼っている | 物理ベースの見え方に揃える: **恒星1灯の硬い明暗境界 + 弱い回り込み光 + 映り込み(IBL) + 露出管理(ACES)** | R1 ライティング/トーンマップ改修（コード量小・効果大） |
| 質感 | 岩は bump のみ・**平面UVが面ごとに引き伸ばされる**（接写で判明） | 法線/粗さマップ + **トライプラナー投影**で、どの面でもクレーターが歪まない | R2 岩マテリアル刷新 |
| ゲーム | 難易度の軸が**速度のみ**で **61.7秒で頭打ち**。配置は一様乱数で「読める」局面がない | **セクター制(約40秒ごとに局面が変わる)** + **公平なパターン生成** | G2 スポナー刷新 |
| ゲーム | スコアが生存時間の比例でほぼ決まり、上手さが点に出ない | **ニアミス / コンボ倍率 / 撃破** を加点源にする | G3 スコア体系 |
| ゲーム | 当たり判定が見た目と最大 ±3 単位ずれる（理不尽な被弾/すり抜け） | 岩の方向別の実寸半径（RadialHull）+ 機体を4球で近似 | G1 判定の正確化（最優先・小工数） |

## 1. 見直しで判明した事実（計測済み）

### 1-1. レンダリング

| 項目 | 現状 | 根拠 |
|---|---|---|
| 色空間 | **正常**（sRGB出力。RenderPass→Bloom→Afterimage を通しても sRGB 128 の灰が 128 で出る） | パイプライン実測。※「色空間が原因で暗い」という仮説は**否定済み** |
| トーンマッピング | なし（`toneMapping=0`）。明部はそのまま白飛び、暗部は持ち上がらない | index.html L613 / L1411 |
| 環境反射 | なし（`scene.environment` 未設定）。金属度 .85 の機体が**映り込むものが無いため灰色の板**に見える | MeshStandard 7種すべて env なし |
| 照明 | `Ambient(0x445577, 2)` + `Directional(0xaaccff, 2.4)`。**全方向から均一に照らす環境光が強く、宇宙らしい陰影(明暗境界)が出ない** | L1400付近のゲーム照明 |
| 材質の偏り | MeshBasic 22 / MeshStandard 7。光に反応しない素材が主体 | マテリアル集計 |
| 影 | なし | shadowMap 無効 |
| 岩の色 | 青紫寄り・明るめ。実際の小惑星の反射率(4〜25%、灰〜褐色)から遠く「おもちゃ感」の原因 | rockMats |
| 岩の表面 | bump のみ。**平面UVのため多面体の各面でテクスチャが引き伸ばされる** | ルックデブ接写で確認（下図B側でクレーターが斜めに流れる） |
| 機体の発光 | 排気スプライトの大きな発光球が機体の輪郭を隠す | 追跡視点の比較 |

### 1-2. ゲームデザイン

| 項目 | 現状 | 問題 |
|---|---|---|
| 難易度 | `speed += dt*6`、110→480 で**61.7秒後に上限** | 以降は同じ状態が続くだけ。上級者ほど退屈 |
| 配置 | 46個の岩を一様乱数で再配置 | 公平性の保証がなく（避けられない壁が起こりうる）、パターンを読む楽しさがない |
| スコア | `距離×10 + 残コア×500` | 生存時間でほぼ決まる。攻めても点にならない |
| 当たり判定 | 岩: `r + 2.2` の球。見た目の表面は判定半径の **0.53〜1.37倍**（r=8 で最大約3.8の隙間 / 約3の食い込み）。翼の半幅 3.75 に対し機体判定 2.2 | 「当たってないのに被弾」「翼が岩を貫通」の両方が起こる |
| 手応え | 被弾時の画面揺れ・減速はある | ヒットストップ、ニアミスの快感、速度感の演出（流線）が無い |
| 継続動機 | BEST スコアのみ | 目標・称号・日替わり等がなく、2回目を遊ぶ理由が弱い |

## 2. ルックデブ比較の結果

同一フレーム(t=2.0)・同一カメラでの輝度計測（`LOOKDEV.measure()`）:

| 指標 | A 現行 | B 提案 | 読み方 |
|---|---|---|---|
| 平均輝度 | 0.088 | 0.059〜0.078 | **暗くしすぎない**（過去FB「ゲーム中が暗い」を再発させない）。調整範囲内で同等に保つ |
| RMSコントラスト | 0.148 | 0.142 | 画面全体の明暗差は同等を維持 |
| 白飛び率 | 0.07% | 0.01% | ACES により発光部の白飛びが 1/7 |
| 質感（目視） | 岩が一様に青く平板、機体は発光球で輪郭が消える | 岩に恒星側の明暗境界とクレーターの凹凸、褐色〜灰の岩種差、寒色リムで輪郭 | |

**分かったこと（本番実装に反映する学び）**
1. 環境光を下げて恒星1灯にすると、**暗くなるのではなく「陰影で形が読める」**ようになる。ただし主光源を 7.5 程度まで上げないと平均輝度が 0.037 まで落ちる（初回試行で確認）。→ 明るさは**主光源と露出で確保し、環境光で確保しない**。
2. bloom は ACES と組み合わせると効きすぎる。閾値 1.0（HDR基準）・強度 .45 程度が適正。
3. 法線マップを平面UVで貼ると多面体の面ごとに歪む → **トライプラナー投影が必須**（R2に含める）。
4. 機体の排気発光球は縮小しても bloom で輪郭を覆う → **発光の形そのもの(細長いプルーム)の再設計**が必要（R3）。

## 3. 方針 — 質感（R: Realism）

### 基本思想「宇宙の光は一方向で、影は真っ黒ではない」
- 光源は**恒星1つ**（暖白・強い・硬い）。反対側は真っ黒ではなく、**星雲/惑星からのごく弱い回り込み光**と**寒色のリム光**で輪郭だけ残す
- 明るさは**露出（ACES トーンマップ）**で決める。emissive は「本当に光っている物（コア・排気・計器・翼端灯）」だけに限定
- 近接岩の視認性は既存の**ヘッドライト**で担保（ゲーム性の要件。現行仕様を継承し、強度のみ新露出に合わせ再調整）

### R1 ライティング / トーンマッピング / 環境反射 〔効果: 大 / 工数: 小〕
- `ACESFilmicToneMapping`（最終段で適用。EffectComposer は中間RTで tone map されないため**最終パスで適用する構成**にする）
- 照明: `Ambient 2.0` → `Hemisphere(空0x2a3e66 / 地0x0a0710, .9)`、主光 `Directional(暖白, 7.5)`、リム `Directional(0x6fb8ff, 2.4)`
- **PMREM による手続き的な宇宙環境マップ**（恒星の輝点+ハロー+淡い星雲。外部HDRI不要）を `scene.environment` に設定
- bloom を HDR 基準に再調整（閾値 1.0 / 強度 .45 / 半径 .3）
- サイト背景（スクロール演出）にも同じ照明モデルを適用し、サイトとゲームの見た目を揃える

### R2 岩マテリアル刷新 〔効果: 大 / 工数: 中〕
- 高さマップ（多オクターブ斑 + 縁が盛り上がるクレーター）を Canvas で生成 → **Sobel で法線マップ化**、粗さマップも同じ高さから派生
- **トライプラナー投影**（`onBeforeCompile` で MeshStandard を拡張。UV に依存しないので面ごとの歪みが消える）
- 岩種 3 系統（C型: 暗灰 / S型: 褐色 / M型: 金属質でわずかに反射）。色は実在小惑星の反射率帯に寄せる
- 大きな岩のみ影を落とす（`castShadow` は近接 N 個に限定してコスト制御）

### R3 機体・発光表現 〔効果: 中 / 工数: 中〕
- 外板: パネル継ぎ目+リベットの法線/粗さマップ、金属度 .86・粗さ .34 で**恒星と環境の映り込み**を出す
- 排気: 球状スプライト → **速度に応じて伸びるプルーム(加算ブレンドの円錐メッシュ+ノイズ)**。輪郭を隠さない
- 被弾時の外板スパーク・焦げ跡（デカール的に emissive を一時点灯）

### R4 空間の奥行き 〔効果: 中 / 工数: 小〜中〕
- 遠景惑星に**フレネルの大気縁光**＋恒星側の昼夜境界
- **塵(ダスト)パーティクル**: 機体近傍に速度方向へ流れる微粒子 → 速度感と奥行きを両立（G4の速度表現と兼用）
- 仕上げパス: ビネット・微粒子ノイズ・周辺の色収差（いずれも控えめ。**レティクル/HUD には掛けない**＝CON-05 を担保）

### 質感の非目標
- 外部HDRI・外部テクスチャ・3Dモデルの導入（オフライン/容量方針を維持）
- レイトレーシング級の表現、動的GI

## 4. 方針 — ゲーム品質（G: Gameplay）

### 基本思想「上手さが画面と点数に出る」
- 避ける・攻める・拾う、の各行動が**その場で気持ちよく反応**し、**点数として残る**
- 難しさは「速さ」だけでなく**局面の種類**で上がる。上級者も3分目に新しい局面に出会う
- 理不尽な被弾をゼロにする（判定の正確化 + 生成の公平性保証）

### G1 当たり判定の正確化 〔最優先 / 工数: 小〕
- 岩ジオメトリごとに**方向別の実測半径テーブル（RadialHull）**を持ち、機体へ向いた方向の表面までの距離で判定
- 機体は**機首・胴・左右翼の4球**で近似（翼半幅 3.75 をカバー）。判定は「見た目より少し甘く」(寛容係数 .9)
- 受け入れ基準: 見た目の表面と判定境界の差が全岩で ±0.6 以内（自動テストで全ジオメトリを検査）

### G2 スポナー刷新とセクター制 〔効果: 大 / 工数: 中〕
- 一様乱数 → **パターン生成**: 「壁に1つ穴」「螺旋」「横切る隕石流」「密集帯＋一本道」「コア誘導ライン」などを組み合わせ
- **公平性保証**: 生成時に機体が通過可能な隙間（機体4球の外形+余裕）が常に1本以上あることを検査。無ければ再生成
- **セクター制**（約40秒ごとに局面が変わり、画面に `SECTOR 02 — DEBRIS FIELD` を表示）

  | セクター | 局面 | 新要素 |
  |---|---|---|
  | 01 OUTER BELT | 疎な岩帯・チュートリアル的 | — |
  | 02 DEBRIS FIELD | 小さく速い破片の群れ | 横移動する岩 |
  | 03 DENSE CORE | 大岩の密集帯と一本道 | 壁パターン |
  | 04 COMET STREAM | 横切る彗星流（予兆の光で警告） | 予兆→回避 |
  | 05+ | 上記の組み合わせを高速で循環 | 速度上限を段階的に引き上げ |

- 速度の頭打ち(61.7秒)を廃止し、**セクターごとに上限が上がる**階段型へ

### G3 スコア体系 〔効果: 大 / 工数: 小〜中〕
- **ニアミス**: 岩の表面から一定距離内をすり抜けると `+NEAR MISS` 加点（音と画面端の流線で即時フィードバック）
- **コンボ倍率**: ニアミス/撃破が途切れずに続くと ×1.0→×4.0。被弾でリセット
- **撃破点**: 機関砲で岩を破壊すると加点（大岩ほど高い）。コア消費とのトレードオフを「攻めの選択」にする
- 結果画面にスコア内訳（距離 / ニアミス / 撃破 / 残コア / 最大コンボ）を表示

### G4 手応え（ジュース） 〔効果: 中 / 工数: 小〕
- 被弾・撃破時の**ヒットストップ**（40〜80ms）
- 速度に応じた**視野角(FOV)の拡大**と流線（R4 ダストと兼用）
- ニアミス時の短い「風切り」音、コンボ段階ごとの音程上昇（既存 SoundEngine の合成で実装）
- **動的BGM強度**: セクターと残シールドで合成音の密度を変える
- SP: 被弾時の `navigator.vibrate`（対応端末のみ・設定でOFF可）

### G5 継続動機（メタ） 〔効果: 中 / 工数: 小〜中〕
- **ランク称号**（到達セクター/スコアで「CADET → PILOT → ACE → VOID RUNNER」）。結果画面とLAUNCH DECKに表示
- **デイリーシード**: 日付から乱数を固定し、全員が同じコースを遊べるモード（オフラインで成立）
- **戦績の共有**: 結果画面から「スコア・称号・セクター」を含む文面を Web Share API / クリップボードで共有（外部送信はしない）
- 自己ベスト履歴（上位5件）を localStorage に保持

### ゲームの非目標
- オンラインランキング（サーバが必要になり、オフライン方針に反する）
- 課金・アカウント

## 5. 性能予算とリスク

| 施策 | 追加コスト | 対策 |
|---|---|---|
| ACES / ビネット等の最終パス | 全画面1パス（GradePass）+ レティクルだけを描く軽量パス | 仕上げ効果は GradePass に集約し、全画面パスは1つだけ増やす |
| PMREM 環境マップ | 起動時のみ（1回生成） | 生成後は静的テクスチャ |
| 影 | 1024² シャドウマップ + 近接岩のみ cast | **Quality の段階劣化の最初の段で影をOFF** |
| 法線/粗さマップ | 512² ×2〜3枚（Canvas生成） | 起動時生成、SPは 256² |
| トライプラナー | 岩シェーダでテクスチャ3回参照 | SP の低品質段では通常UVへ切替 |

- **既存の Quality 段階劣化（3秒継続で1段階）に「影 → 仕上げパス → 法線マップ」の順で降格段を追加**し、SPで60fpsを割らないことを受け入れ基準にする
- リスク: 暗さの再発 → 平均輝度を**自動テストで下限監視**（現行 0.088 の ±20% 以内）
- リスク: CON-05 → 操縦席のレティクルは**ゲームの3Dシーン内のメッシュ**のため、そのままではトーンマップ・仕上げの影響を受ける。
  レティクルを専用シーンに分け、トーンマップの後に合成する構成とし、黒背景上の画素値が現行と一致することをテストで固定する（詳細: [09b](09b-look-lighting.md) §3.1）。DOM カーソルは WebGL の外なので影響なし

## 6. フェーズ計画（承認後に SDD 詳細設計 → TDD 実装）

優先度は「効果 ÷ 工数」と「理不尽の解消」を重視。質感とゲームを交互に進め、毎フェーズでデプロイして体感確認できるようにする。

| Phase（詳細設計） | 内容 | 主な受け入れ基準（テスト化） |
|---|---|---|
| **P1** ([09a](09a-collision.md)) | G1 当たり判定の正確化 | 全岩ジオメトリで見た目⇔判定の差 ±0.6 以内 / 翼端の接触を検出 |
| **P2** ([09b](09b-look-lighting.md)) | R1 照明・ACES・PMREM・bloom 再調整（ゲーム+サイト） | toneMapping 有効 / env 設定済み / 平均輝度が現行±20% / 白飛び率 ≤ 現行 / CON-05 不変 |
| **P3** ([09c](09c-spawner-sectors.md)) | G2 パターンスポナー + セクター制 + 階段型速度 | 全生成パターンで通過可能な隙間 ≥1 を 1000 回試行で保証 / 40秒ごとのセクター遷移 |
| **P4** ([09d](09d-rock-material.md)) | R2 岩マテリアル（法線/粗さ/トライプラナー/岩種） | 法線・粗さマップ適用 / トライプラナー有効 / 3岩種の色域 |
| **P5** ([09e](09e-score-feel.md)) | G3 スコア体系 + G4 手応え | ニアミス判定・コンボ倍率・内訳表示 / ヒットストップ時間 |
| **P6** ([09f](09f-ship-space-finish.md)) | R3 機体・排気プルーム + R4 惑星大気・ダスト・仕上げパス | 排気が機体輪郭を覆わない（輪郭ピクセル占有率） / 仕上げパスが HUD に掛からない |
| **P7** ([09g](09g-meta-docs.md)) | G5 称号・デイリーシード・共有 / ドキュメント・説明ページ整合 | 同一日付で同一コース / 共有文面生成 / サイトの遊び方説明と仕様の一致 |

各フェーズで: 既存テスト 183 件 + 新規テストが全て緑 → commit/push → GitHub Pages 反映確認。

> サイトの説明章（FLIGHT/WEAPONS/SURVIVAL）は、P3・P5 でゲーム仕様が変わった時点で説明文と演出を追随させる（ニアミス/コンボ/セクターの説明追加）。

## 7. 外部からの用意が必要なもの

**必須: なし。** すべて Canvas 生成・シェーダ・Web Audio 合成で実装できる（ルックデブで実証済み）。

任意（品質をさらに上げたい場合のみ。導入するならライセンス確認が必要）:
- 実在天体写真ベースの星空キューブマップ（CC0 等） — 現行の手続き星空でも成立
- 録音ベースの効果音 — 現行の合成音で成立

## 8. 判断をお願いしたい点

1. **フェーズ順**: 上記 P1〜P7（判定→照明→生成→…）でよいか。見た目を先に揃えたい場合は P2→P4→P6 を先行させる案もある
2. **ゲームの方向性**: セクター制・ニアミス/コンボ・デイリーシードは「アーケード寄り」の強化。よりシミュレーター寄り（慣性・燃料管理など）を望む場合は G2〜G3 を組み替える
3. **サイト背景への適用範囲**: R1〜R2 をスクロール演出にも同時適用するか（推奨: 同時。ゲームとの見た目の一貫性のため）
