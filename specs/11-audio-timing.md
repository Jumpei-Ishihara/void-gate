# SPEC 11 — 効果音のタイミング調整

状態: **Verified（2026-09-23 phaseAU 7/7・run-all 21スイート332テスト ALL GREEN）** ／ 依頼: 「効果音のタイミングが遅れているように感じる」 ／ 前提: SPEC-10 Verified ／ 外部素材: 不要

## 1. 調査結果（計測）

| 観点 | 結果 | 判定 |
|---|---|---|
| 入力 → 発音 | 機関砲は `mousedown` / `touchstart` で即時に `fire()` → 同じ処理内で発音（`click` の遅延なし） | 問題なし |
| 音声出力の遅延 | `baseLatency` 5ms + `outputLatency` 24ms = **約29ms**（この環境。Bluetooth イヤホンでは 150〜250ms になり得る） | 通常は問題なし |
| 音の立ち上がり | 全効果音をオフライン描画して測定: 全帯域で**ピークの50%到達 5ms 以内** | 問題なし |
| 爆発音の中身 | 300Hz 以上の成分のピークが全体の約 1/4（0.06）。低音主体でノートPC・スマホのスピーカーでは**立ち上がりが鈍く遅れて聞こえる** | **要改善** |
| ニアミス音 | 岩の中心が機体を**通過した後**に鳴り始める → 耳には「すれ違った後に鳴る」 | **要改善** |
| サイト WEAPONS 章 | 着弾閃光（ta .49）が**無音**。爆発音は凍結解除（tl .80）に鳴り、爆発の広がり（ta .55）と一致しない | **要改善** |
| サイト SURVIVAL 章 | 接触音は一致。CRITICAL の警告音が凍結解除に鳴り、シールドが砕ける瞬間（ta .50〜）と一致しない | **要改善** |

## 2. 要件

| ID | 要件 |
|---|---|
| AU-01 | 全効果音の立ち上がり（全帯域・300Hz 以上）がピーク50%到達 10ms 以内 |
| AU-02 | 爆発音の冒頭に高域の「破裂」成分を加え、300Hz 以上のピークを 0.15 以上に（小型スピーカーでも瞬間が分かる） |
| AU-03 | ニアミス音は**すれ違う瞬間にピーク**が来るよう先行して鳴らす（予測で 0.12 秒 + 端末の出力遅延ぶん前に開始）。得点は従来どおり通過時に確定し、同じ岩で音は1回 |
| AU-04 | サイトの章の効果音は**映像の時間（ta）**で発火する: WEAPONS の着弾（ta .49）に着弾音、爆発の広がり（ta .55）に爆発音 / SURVIVAL の砕散（ta .505）に警告音 |
| AU-05 | AudioContext は `latencyHint: 'interactive'` を明示 |
| AU-06 | 既存テスト全グリーン |

## 3. 受け入れテスト（tests/phaseAU.js）

| テストID | 検証 |
|---|---|
| AU-T01 | 全効果音の t50 ≤ 10ms（全帯域・高域） |
| AU-T02 | 爆発音の高域ピーク ≥ 0.15 |
| AU-T03 | `whoosh(pan, 0.12)` の音量ピークが 120ms ±20ms |
| AU-T04 | ゲーム: 通過 0.12 秒前の岩で風切り音が先行して鳴り、通過時に得点・音は重複しない |
| AU-T05 | サイト WEAPONS: ta .49 通過で着弾音、tl .80（ta .50）では爆発音なし、ta .55 通過で爆発音 |
| AU-T06 | サイト SURVIVAL: 警告音は ta .505 通過時（tl .80 ちょうどでは鳴らない） |

## 4. 実施結果

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 爆発音の高域ピーク（小型スピーカーで聞こえる立ち上がり） | 0.06 | **0.27〜0.36**（冒頭に高域ノイズ+短いクリックの「破裂」） |
| ニアミス音 | 岩の中心が通過した後に鳴り始める | 通過の 0.12 秒+出力遅延ぶん前に予測して鳴らし、**すれ違う瞬間にピーク**（ピーク時刻の実測 125ms / 目標 120ms）。予測が外れた場合（機体が避けた等）は通過時に得点されず、音だけ鳴る |
| サイト WEAPONS | 着弾閃光が無音、爆発音は凍結解除時 | 着弾閃光の誕生（ta .49）に着弾音、爆発の広がり開始（ta .55）に爆発音 |
| サイト SURVIVAL | 警告音は凍結解除時 | シールドが砕け始める瞬間（ta .505） |
| AudioContext | 既定 | `latencyHint: 'interactive'` を明示 |

- 端末の出力遅延（`outputLatency + baseLatency`）を取得し、予測できる音（ニアミス）はその分だけ前倒しする。
  機関砲・被弾・撃破など**予測できない音は前倒しできない**ため、Bluetooth イヤホン等では端末側の遅延（150〜250ms）が残る
- テスト用に `SoundEngine._render(name, ...)`（オフライン描画で立ち上がり時刻を計測）と種類ごとの発音回数 `counts` を追加
