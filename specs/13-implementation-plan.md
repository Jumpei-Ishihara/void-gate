**フェーズの順序の理由**: K1 の間は DOM HUD を残す（右の計器が担っていたシールド・コア表示の行き先がまだないため）。

## 2. 各フェーズの進め方（共通手順）

1. **RED**: `tests/phaseKn.js` を詳細設計の受け入れテスト表どおりに作成し、実行して**失敗することを確認**
2. **既存テストの改訂**: 詳細設計の「既存テストの改訂」にあるものだけを反映（理由をテストのコメントに残す）
3. **GREEN**: 実装 → phaseKn 全合格
4. **回帰**: `tests/run-all.js` にスイートを追加して全実行 → 全スイート合格
5. **目視**: プレビューで PC（1280×720）と SP（667×375 横）の画像を確認（通常・シールド 1・シールド 0。K3 はロック・起動演出も）
6. **commit → push → Pages 反映確認**（`gh run watch` と本番 URL の取得。起動してコンソールエラーなし）
7. 詳細設計の状態を `Verified（日付・件数）` に更新

問題がなければ次のフェーズへ連続して進む。

## 3. フェーズ別の要点

### K1 物理部品（最も慎重に進めるフェーズ）

- **最初に計測系を作る**: `debug().ck.mask()`（不透明部品のマスク・占有率・中央域・操縦桿の位置）を先に実装し、
  旧操縦席で 21.6% / 中央域 0 画素が再現できることを確認してから部品を置き換える
- CON-05: K1-T08 を最初に合格させ、以降すべての変更で維持する（レティクルのコードには触れない）
- 撤去 → 新設の順ではなく、**新しい `buildCockpit()` を丸ごと差し替え**、`cptFx` の互換（greebles / bezels / lamps / alertLamp / alertLight）を保つ
- 輝度: 発光は `glowK = 1.6` から始め、K1-T09（白飛び ≤ .1%）で超える場合は下げる。既存の基準値は動かさない
- 旧 `drawDash()` が担っていた被弾グリッチ（FX-06）を `updateCockpit` へ移す（見落としやすい）

### K2 ホログラム

- `holoPanel` を先に作り、キー判定による再描画の抑制（K2-T07）を最初に通す
- 状態色の切替はパネルの再描画と発光材質の色変更を 1 か所（`updateCockpit`）でまとめて行う
- DOM HUD は CSS だけで隠す（`hud()` を変えない＝既存テスト F5-T08・F3-T09 を壊さない）

### K3 ロック札・起動演出・SP

- 起動演出は描画側だけで完結させ、`st` のゲーム状態（距離・速度・判定）に触れない（K3-T04 で `st.dist` の進行を確認）
- 文字の実寸はデバッグ API の計算値でテストし、最後に SP 実寸の画像で目視
- 文書（README / DESIGN.md / SPEC-00）はこのフェーズでまとめて更新
